# Streamlit web demo

## Start

Fastest option: double-click `run_c2_web.cmd` in the repository root.

The local environment is stored at `.venv`. No activation is required by the
launcher. To run it manually:

```powershell
cd C:\HackathonFPT\hack2026
.\.venv\Scripts\python.exe -m streamlit run c2/streamlit_app.py
```

Open the URL printed by Streamlit, normally `http://localhost:8501`.

The page automatically offers this local test clip when present:

```text
c2/cache/web_test_realtime.mp4
```

Rebuild it from the extracted DMD material with:

```powershell
python c2/make_web_test_video.py --dmd-root C:\DMD\dmd
```

Timeline: safe `0–6s`, phone `6–15s`, yawn `15–23s`, long eye closure
`23–31.5s`. The MP4 contains raw frames; predictions are generated by the web
app during replay.

## Use

1. Upload `c2/cache/web_test_realtime.mp4`, or use the bundled sample if it is
   present.
2. Leave calibration at 2 seconds.
3. Keep the phone detector interval at 5 frames for CPU.
4. Press **Start realtime replay**.
5. The browser receives the rendered HUD frame-by-frame at the selected speed.

This web MVP deliberately uses MP4 replay. `st.camera_input` is a still-image
widget, not a continuous webcam stream; adding browser webcam requires a
WebRTC component and is a separate deployment concern.

The sample is generated locally from DMD research footage. Keep it local and
do not redistribute or deploy it publicly.
